Instagram 장소 추출 enqueue-only 리팩토링

작업 상태를 서버가 추적하던 구조를 제거하고, Public API는 Cloud Tasks enqueue만 담당하도록 단순화했습니다. 실제 추출과 최종 저장은 같은 API 런타임의 Internal endpoint에서 수행합니다.

canonical places란?

canonical은 별도 테이블명이 아니라 장소의 기준 원본이라는 의미입니다. 추출 결과는 최종적으로 places에 저장되고, 같은 provider와 provider place ID가 있으면 중복 행 대신 업데이트합니다.

현재 PR의 Internal 요청에는 roomId가 없으므로 pins 연결은 수행하지 않습니다. POST /api/v1/rooms/{roomId}/pins 및 POST /api-internal/v1/tasks/pins 전환과 방별 pin 저장은 후속 PR 범위입니다.

PRDAPP_ENV=prod

현재 코드에서는 별도 CLOUD_TASKS_OIDC_AUDIENCE 환경변수를 사용하지 않습니다. audience는 API의 APP_BASE_URL로 통일됩니다.

애플리케이션 build, TypeScript typecheck, tsc typecheck 통과
infra typecheck, Biome 검사, git diff --check 통과

로컬 Internal QA에서 확인된 AI_EXTRACTION_FAILED 502는 AI 추출 로직의 별도 수정 PR 범위입니다. 해당 실패 시 최종 장소가 저장되지 않는 것은 정상입니다.

현재 PR의 범위와 후속 작업

  • 완료: 작업 상태 테이블/조회 API 제거, enqueue-only 응답, OIDC 보호 Internal endpoint, 최종 places 저장
  • 완료: Public/Internal을 동일 API 런타임으로 통합하고 Worker Cloud Run 배포 제거
  • 후속 PR: /api/v1/rooms/{roomId}/pins 및 /api-internal/v1/tasks/pins 계약

  • 범위 제외: 푸시 알림

운영 참고

PRD Secret의 APP_BASE_URL은 기존 API Cloud Run 서비스 URL이어야 합니다. Secret 새 버전은 앱 재배포/재시작 후 부팅 시 반영되며, Cloud Tasks가 생성하는 audience와 Internal guard가 검증하는 audience는 같은 API URL을 사용합니다.
